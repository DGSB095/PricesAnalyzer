# Оптимизация товарных закупок малого бизнеса

Первый backend-прототип проекта «Оптимизация товарных закупок малого бизнеса на
основе анализа рыночных тенденций». Он импортирует предложения, хранит историю
в SQLite и сравнивает полную стоимость заданной закупки. CSV демонстрирует
выбор между поставщиками, Books to Scrape — HTTP-загрузку и HTML-парсинг.
Оба набора учебные: это не база реальных рыночных цен.

## Установка в Windows PowerShell

Нужен Python 3.11 или новее. Из корня репозитория:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m prices_analyzer --help
```

Далее команды используют Python из локального окружения без обязательной активации
и без изменения ExecutionPolicy. Если окружение активировано, можно писать просто
`python -m prices_analyzer`. Для установки без pytest: `pip install -e .`.
Зависимости объявлены в `pyproject.toml`: Requests, Beautiful Soup, pytest для тестов.
Остальное — стандартная библиотека. На Linux/macOS путь Python: `.venv/bin/python`.

## Быстрая демонстрация без сети

```powershell
.\.venv\Scripts\python.exe -m prices_analyzer demo
.\.venv\Scripts\python.exe -m pytest -q
```

`demo` создаёт отдельную временную БД в новой подпапке `backend/db/`, импортирует
CSV дважды, разбирает сохранённый HTML, читает последние наблюдения и историю,
показывает сравнение и удаляет только созданную временную папку. Можно запускать
повторно. Пользовательский `--db` не используется. Для другой родительской папки:
`demo --directory PATH`. Тесты всегда используют временные папки и не меняют
основную БД; сетевой доступ в обычных тестах запрещён.

Ожидаемо: первый импорт — 8 наблюдений, повторный — 8 дубликатов, HTML — 2 записи.
У 3 учебных товаров 7 предложений, одно предложение имеет 2 наблюдения.
Для 10 пачек бумаги с пределом 7 дней поставщик Б стоит **1300 RUB**, поставщик А —
**2500 RUB**. Большая партия и долгий срок исключаются; неизвестная доставка даёт
неполный расчёт. Безусловный победитель среди всех предложений не объявляется.

## Команды CLI

Глобальный `--db` ставится **перед командой**. По умолчанию используется
`backend/db/offers.sqlite3` независимо от текущего рабочего каталога. Также есть
`PRICES_ANALYZER_DB`; `--db` имеет приоритет. Относительный явно заданный путь
считается от текущей рабочей папки. Повторный `init-db` безопасен.

```powershell
.\.venv\Scripts\python.exe -m prices_analyzer --db db/offers.sqlite3 init-db
.\.venv\Scripts\python.exe -m prices_analyzer import-csv data/sample_offers.csv --dry-run
.\.venv\Scripts\python.exe -m prices_analyzer import-csv data/sample_offers.csv
.\.venv\Scripts\python.exe -m prices_analyzer import-csv data/sample_offers.csv
.\.venv\Scripts\python.exe -m prices_analyzer list --product demo:paper-a4 --source demo
.\.venv\Scripts\python.exe -m prices_analyzer list --supplier demo:b
.\.venv\Scripts\python.exe -m prices_analyzer history --source demo --offer paper-b
.\.venv\Scripts\python.exe -m prices_analyzer compare --product demo:paper-a4 --quantity 10 --max-days 7
.\.venv\Scripts\python.exe -m prices_analyzer import-csv data/invalid_offers.csv
```

`invalid_offers.csv` содержит 1 корректную и 6 ошибочных строк; ожидается код 1,
сохранение корректной записи и номера ошибочных строк. Сводка импорта показывает
обработано / добавлено / пропущено как дубликаты / отклонено.

Коды завершения: **0** — успех; **1** — частичный импорт с отклонёнными строками
или карточками; **2** — ошибка аргументов, файла, сети, схемы или сохранения.
Сбой сохранения откатывает весь пакет, даже если до сбоя были вставлены записи.
При сетевом сбое посередине обхода ничего из этого сбора не сохраняется.
`--dry-run` проверяет данные и дубликаты на копии БД в памяти: не создаёт и не
меняет целевой файл. Без dry-run перед первым импортом нужен `init-db`.
У всех команд есть `--help`.

### Сохранённый HTML — без сети

```powershell
.\.venv\Scripts\python.exe -m prices_analyzer import-html tests/fixtures/books_page.html --observed-at "2026-11-22T09:00:00Z"
.\.venv\Scripts\python.exe -m prices_analyzer import-html tests/fixtures/books_page.html --observed-at "2026-11-22T09:00:00Z"
.\.venv\Scripts\python.exe -m prices_analyzer list --source books
.\.venv\Scripts\python.exe -m prices_analyzer history --source books --offer 1000
```

Время снимка задаётся явно; повтор с тем же временем даёт дубликаты. Для HTML
не с главной страницы укажите исходный `--page-url`, чтобы правильно разрешить
относительные ссылки. Офлайн-импорт разбирает только переданный файл и не идёт
по пагинации. Допускается `--dry-run`.

### Живой HTML-сбор — нужна сеть

```powershell
.\.venv\Scripts\python.exe -m prices_analyzer collect books --max-pages 1 --dry-run
.\.venv\Scripts\python.exe -m prices_analyzer collect books --max-pages 2
.\.venv\Scripts\python.exe -m prices_analyzer list --source books
```

Это настоящий запрос к `https://books.toscrape.com/`, без подмены сохранённым
файлом при ошибках. Время сбора фиксируется в UTC; повторный живой сбор создаёт
новое наблюдение даже при неизменной цене. Валюта — GBP, поставщик один.
Отсутствующие расходы, партия и срок не выводятся из наличия товара.

Настройки HTTP находятся в `config.py`: тайм-аут 15 секунд на операции Requests,
пауза 0,5 секунды, 2 повтора (итого до 3 попыток) при сетевых сбоях и HTTP
429/500/502/503/504. Между повторами есть задержка; длинный или нестандартный
Retry-After завершает сбор с сообщением, не обходится. 403/404 не повторяются.
Тайм-аут не является общим пределом длительности всего обхода.

## Формат CSV и валидация

UTF-8, в том числе BOM; разделитель — запятая; строки в кавычках — по обычным
правилам CSV. Все перечисленные заголовки обязательны, неизвестные и повторные
столбцы отклоняются:

```text
product_id,product_name,unit,supplier_id,supplier_name,source,external_id,url,price,currency,minimum_quantity,delivery_cost,extra_cost,delivery_days,observed_at,availability
```

| Поля | Правило |
|---|---|
| product_id | Явный ID `source:локальный-id`, например `demo:paper-a4`; никакого слияния по названию |
| product_name, supplier_id, supplier_name | Непустые название товара, ID и название поставщика |
| source, external_id, url | Источник (`demo`, `books`), ID предложения внутри источника, HTTP(S)-ссылка |
| unit | `pcs`, `pack`, `kg`, `g`, `l`, `m`; никакого пересчёта единиц |
| price, currency | Неотрицательная десятичная цена; `RUB`, `GBP`, `USD`, `EUR`, `CNY` |
| minimum_quantity | Положительное количество или пусто |
| delivery_cost, extra_cost | Неотрицательные суммы или пусто; явный `0` означает отсутствие расхода |
| delivery_days | Целое неотрицательное число дней или пусто |
| observed_at | Обязательный ISO 8601 с часовым поясом, например `2026-11-22T12:00:00+03:00` |
| availability | `in_stock`, `out_of_stock` или пусто |

Пустые необязательные значения сохраняются как NULL. Цена, валюта, единица и время
не угадываются. Деньги и количество используют Decimal, без float; ввод — до 28
цифр и 28 десятичных разрядов, с точкой, без экспоненты и разделителей тысяч.
Локальная точность расчёта 160 знаков позволяет выполнять операции в этих пределах
без округления. Результат не округляется автоматически до копеек.
Номер ошибки — физическая строка CSV, для многострочной записи последняя строка.
При синтаксически повреждённом CSV разбор прекращается с ошибкой; предшествующие
корректные записи могут быть импортированы.

`sample_offers.csv` и `invalid_offers.csv` явно учебные, с доменом example.com.
Это наш формат, не нативная выгрузка какого-либо маркетплейса.

## SQLite, история и сравнение

Таблицы: `products`, `suppliers`, `offers`, `observations`. Внешние ключи включаются
при каждом подключении. SQL параметризован, запись пакета — одна транзакция.
Деньги записываются десятичными строками TEXT, времена — в UTC с микросекундами.

Предложение уникально по `(source, external_id)`. Наблюдение уникально по
`(offer_id, observed_at_UTC)`. Тот же момент и те же условия — дубликат;
`1.0` и `1.00` эквивалентны. Тот же момент с другими условиями — конфликт и откат
всего сохранения. Новое время всегда добавляет историю. Последние записи выбираются
по `observed_at DESC, id DESC`; уникальность времени внутри предложения предотвращает
неоднозначные совпадения, ID обеспечивает детерминированный дополнительный порядок.

Цена, валюта, партия, расходы, срок и наличие находятся в наблюдениях. Изменение
названия/единицы при том же товарном ID или привязок/URL предложения считается
конфликтом: автоматической миграции идентичности прототип не выполняет.

Полная стоимость = цена × количество + доставка + дополнительные расходы.
Сервис разбивает результаты на группы валют и единиц; расчёт отклоняет смешанную
группу. Слишком большая минимальная партия, долгий срок и явное отсутствие товара
исключают предложение. Заказ не увеличивается автоматически. Неизвестные партия,
срок или расходы дают неполный результат. Ранжируются только полные допустимые
варианты; показываются составляющие и причины. Неизвестное наличие само по себе
не заменяет условия; его отображают в list/history, подтверждённый остаток не проверяется.

## Структура и обязанности

```text
backend/
  prices_analyzer/
    cli.py                 argparse и вывод
    config.py              пути и HTTP-настройки
    models.py              dataclasses
    validation.py          общий контракт и проверка
    services.py            получить → проверить → сохранить, demo
    database.py            SQLite и история
    comparison.py          расчёт и ограничения
    sources/
      csv_source.py        CSV
      books_source.py      Requests и Beautiful Soup
  db/                      локальные БД, исключены из Git
  data/                    контрольные CSV
  tests/                   pytest и небольшие HTML-фикстуры
  docs/data_sources.md     проверенные источники и ограничения API
  pyproject.toml           зависимости и настройки pytest
  README.md
```

CLI не содержит SQL, HTML-селекторов или вычисления стоимости. Парсеры не знают
о SQLite. Отдельный сервис соединяет этапы, поэтому будущие Go/React смогут
использовать основной функционал через отдельную интеграцию.

## Проверки и ограничения

22.11.2026 на Windows и Python 3.14.6: **44 pytest-теста прошли**; выполнен
офлайн-demo. Отдельный живой `collect books --max-pages 2` обработал и сохранил
**40 карточек без ошибок**. История прочитана новым процессом CLI из сохранённой
SQLite. Загрузка главной страницы для фикстуры отдельно дала HTTP 200.
В песочнице сетевой доступ запрещён, поэтому сетевые проверки выполнялись с
разрешённым внешним доступом. Python 3.11 отдельно не проверялся.

Фикстура `books_page.html` содержит две карточки, извлечённые из живого ответа
22.11.2026, и сокращённую навигацию. Время `09:00Z` в demo — фиксированная учебная
метка снимка для воспроизводимости, не заявление о времени HTTP-запроса.
`books_broken.html` — специально повреждённая тестовая разметка.

Данные Books to Scrape не дают возможности изучать реальный рынок; доставка,
налоги, партии и сроки неизвестны. Прототип не оценивает свежесть наблюдений,
не конвертирует валюты и не сопоставляет источники автоматически. Нет сервера,
Go/React, PostgreSQL, Docker, ML, прогнозирования и фоновых задач.

Проверка официальных API и подтверждённых файловых форматов находится в
[docs/data_sources.md](backend/docs/data_sources.md). Документы WB оказались недоступны,
основная динамическая спецификация Ozon не прочиталась; эти ограничения отмечены
явно. Незавершённых адаптеров маркетплейсов нет.
